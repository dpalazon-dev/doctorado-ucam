# System Principles

These principles define the permanent architectural foundations of ResearchOS.

They are intentionally independent from any technology, framework or implementation.

Every architectural decision, feature, workflow or interface should reinforce these principles rather than compromise them.

---

# 1. One System

ResearchOS is a single operational system.

It may internally consist of multiple domains, entities, models, use cases, but the researcher should perceive and interact with a single coherent environment.

No feature should behave as an isolated tool.

Every capability belongs to the same core operational model.

---

# 2. Context is the Primary Asset

Information alone has little value without context.

Information, Knowledge, Context have different meanings, they don’t mean the same and represent different concepts that we need to exploit at different levels.

Every document, note, experiment, task, hypothesis or conversation should exist within a network of meaningful relationships.

The system should be capable of creating context whenever it’s needed, allowing knowledge to remain understandable and actionable long after it was created.

Context must never be sacrificed for convenience.

---

# 3. Reduce Cognitive Load

The system exists to reduce mental overhead, not increase it.

Researchers should spend their cognitive resources on reasoning, discovery and scientific thinking rather than on remembering locations, coordinating tools or managing repetitive work.

Whenever multiple solutions exist, the preferred solution is the one that minimizes cognitive effort.

---

# 4. Intelligence Augments, Never Replaces

Artificial Intelligence exists to extend the researcher's capabilities.

It should remember.

It should organize.

It should recommend.

It should automate.

It should assist.

It should never replace scientific judgement, critical thinking or intellectual responsibility.

The researcher always remains the final decision maker.

---

# 5. Knowledge Exists to be Operated On

Knowledge is not collected for archival purposes.

Every piece of knowledge should be usable.

Documents should generate ideas.

Ideas should become hypotheses.

Hypotheses should lead to experiments.

Experiments should generate evidence.

Evidence should improve knowledge.

The system should continuously enable this operational cycle.

---

# 6. Everything Has a Single Source of Truth

Every entity within the system should have one authoritative representation.

Duplicate information creates inconsistency, increases maintenance costs and breaks trust.

The system should reference knowledge instead of replicating it whenever possible.

---

# 7. Automation Should Remove Repetition

Automation is not a goal by itself.

Its purpose is eliminating repetitive operational work.

The researcher should invest time where human judgement creates value.

Everything else should be considered a candidate for automation.

---

# 8. The System Evolves Incrementally

ResearchOS is expected to evolve continuously.

New capabilities should integrate naturally into the existing operational model rather than introducing disconnected subsystems.

Growth should increase capability without increasing complexity.

---

# 9. User Experience is an Architectural Requirement

User experience is not a visual layer added after implementation.

It is a fundamental architectural concern.

Every interaction should reduce friction, preserve focus and maintain continuity of thought.

The best interface is the one that disappears during research.

The researcher should think about science, not about software.
