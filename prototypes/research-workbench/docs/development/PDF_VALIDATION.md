# T02 — validación de PDF antes de publicar la importación

Decisión del coordinador, 2026-10-02. Complementa SPEC-002 y DATA; implementación y medidas pendientes.

Se autoriza `pdf = { version = "=0.10.0", default-features = false }` (MIT) para un probe estructural backend. El [registro de la versión](https://crates.io/api/v1/crates/pdf/0.10.0) publica checksum `de084796ae1744b0ae6b2b1e9368ed87bd43043ca410363edb72155ea68245db`. Lockfile, avisos de licencia y compilación MSVC deberán verificarse en T02.

El trabajo de DocumentStore copia y calcula hash en streaming, fuera del hilo DB/ventana y de cualquier transacción SQL. Sobre el staging propio, una sola validación activa por biblioteca lee hasta 524288001 bytes para detectar crecimiento o exceso del máximo de 500 MiB. El buffer se mueve al parser sin clonarlo. Se permite esperar asíncronamente el turno de validación; no se bloquea UI ni se mantiene una transacción durante esa espera. No se introduce mmap ni unsafe propio.

Con [FileOptions::uncached](https://docs.rs/pdf/0.10.0/pdf/file/struct.FileOptions.html), configuración strict y load(buffer), comprobar trailer/xref/catálogo, al menos una página, resolución de la primera página y MediaBox con dimensiones finitas positivas. No reparar silenciosamente un documento, decodificar Contents/imágenes/fuentes, ejecutar JavaScript/acciones ni alterar bytes. Es una comprobación mínima de estructura navegable, no una certificación ISO o de render de todas las páginas. PDF.js conserva la responsabilidad de mostrar errores de lectura posteriores.

En v0.1 se rechaza cualquier cifrado declarado, incluido usuario vacío o restricciones de propietario, con `InvalidPdf` y diagnóstico seguro de PDF protegido no compatible con esta versión. Si la carga exige contraseña o falla descifrado, mismo diagnóstico. Si puede abrirse, revisar [Trailer.encrypt_dict](https://docs.rs/pdf/0.10.0/pdf/file/struct.Trailer.html); no buscar la cadena `/Encrypt` en texto, que puede ser contenido normal. No se ofrece UI de contraseña ni se persiste una copia descifrada. Esta política conservadora puede rechazar documentos que otros lectores abren: es una limitación explícita del piloto.

Otros errores de parser producen `InvalidPdf` con «No se puede validar este PDF», sin afirmar corrupción inequívoca ni exponer error crudo/rutas. Distinguir I/O del original (`SourceUnreadable`) de fallos de almacenamiento administrado. No publicar preview ni Paper exitoso antes de validar; mantener intención/error recuperable conforme a DATA.

Pruebas: PDF real con xref clásico, xref/object streams e incremental; texto renombrado, falsa cabecera/EOF, trailer/root/pages inválidos, Count sin página resoluble, primera página/caja inválida y ciclo; PDF realmente protegido con contraseña y con usuario vacío; `/Encrypt` como contenido ordinario; archivo válido cercano/al límite y exceso/crecimiento durante lectura; staging válido tras mover original. Usar únicamente fixtures sintéticas. No afirmar soporte máximo o latencias sin medir.

El buffer está acotado, pero estructuras comprimidas del PDF pueden consumir memoria adicional: [ParseOptions](https://docs.rs/pdf/0.10.0/pdf/object/struct.ParseOptions.html) no ofrece una cuota de expansión. Serializar limita concurrencia, no la RAM total de un archivo adverso. Registrar coste observado conforme a QUALITY; no presentar un timeout o spawn_blocking como aislamiento de memoria.

Limitación concreta del parser fijado, verificada durante T02fix1 en su fuente local: pdf-0.10.0/src/object/types/pagesnode.rs:55–60 inicia la búsqueda con page_limited(..., 16) y rechaza al agotar ese presupuesto; file.rs:825–827 utiliza esa búsqueda. Por ello una jerarquía de páginas válida excepcionalmente profunda puede no superar el probe. Se conserva el diagnóstico seguro «No se puede validar este PDF», sin afirmar corrupción. No se sustituye la dependencia en este corte. La resolución propia de MediaBox debe admitir herencia y detectar ciclos sin añadir un umbral arbitrario distinto ni reclamar soporte ilimitado que el parser no ofrece.

Se descartó mmap por su contrato unsafe ante modificaciones externas. También Windows.Data.Pdf: [Microsoft exige identidad de paquete para PdfDocument/PdfPage](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/winrt-api-desktop-app-support), que el NSIS definido no proporciona. No se cambia el empaquetado para incorporar ese API. La investigación completa se conserva en `work/reviews/task02-pdf-validation-preflight.md`.
