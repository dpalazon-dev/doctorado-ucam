# T02 — PDF validation before publishing an import

Coordinator decision, 2026-10-02. Complements SPEC-002 and DATA; implementation and measurements remain pending.

Authorize `pdf = { version = "=0.10.0", default-features = false }` (MIT) for a backend structural probe. The [version registry](https://crates.io/api/v1/crates/pdf/0.10.0) publishes checksum `de084796ae1744b0ae6b2b1e9368ed87bd43043ca410363edb72155ea68245db`. Verify the lockfile, license notices and MSVC build in T02.

DocumentStore copies and hashes as a stream, outside the DB/window thread and any SQL transaction. On its own staging file, one active validation per library reads up to 524288001 bytes to detect growth or exceeding the 500 MiB maximum. Move the buffer into the parser without cloning it. Asynchronous waiting for a validation turn is allowed; do not block the UI or retain a transaction during that wait. Introduce neither mmap nor custom unsafe code.

Using [FileOptions::uncached](https://docs.rs/pdf/0.10.0/pdf/file/struct.FileOptions.html), strict configuration and load(buffer), check trailer/xref/catalog, at least one page, resolution of the first page, and MediaBox with positive finite dimensions. Do not silently repair a document, decode Contents/images/fonts, execute JavaScript/actions or alter bytes. This is a minimum navigable-structure check, not ISO certification or proof that every page renders. PDF.js remains responsible for displaying later reading errors.

In v0.1 reject any declared encryption, including empty-user or owner restrictions, with `InvalidPdf` and a safe diagnostic indicating that protected PDFs are unsupported in this version. If loading requires a password or decryption fails, use the same diagnostic. If loading succeeds, inspect [Trailer.encrypt_dict](https://docs.rs/pdf/0.10.0/pdf/file/struct.Trailer.html); do not search for `/Encrypt` in text, where it may be ordinary content. Provide no password UI and persist no decrypted copy. This conservative policy can reject documents other readers open: it is an explicit pilot limitation.

Other parser errors produce `InvalidPdf` with “This PDF cannot be validated”, without asserting unequivocal corruption or exposing raw errors/paths. Distinguish source I/O (`SourceUnreadable`) from managed-storage failures. Publish no preview or successful Paper before validation; retain a recoverable intent/error according to DATA.

Tests: real PDF with classic xref, xref/object streams and incremental updates; renamed text, false header/EOF, invalid trailer/root/pages, Count without a resolvable page, invalid first page/box and a cycle; genuinely password-protected and empty-user PDFs; `/Encrypt` as ordinary content; a valid file near/at the limit and excess/growth during reading; valid staging after moving the original. Use only synthetic fixtures. Do not claim maximum support or latency without measurement.

The buffer is bounded, but compressed PDF structures can consume additional memory: [ParseOptions](https://docs.rs/pdf/0.10.0/pdf/object/struct.ParseOptions.html) provides no expansion quota. Serialization limits concurrency, not the total RAM of an adversarial file. Record observed cost according to QUALITY; present neither a timeout nor spawn_blocking as memory isolation.

Specific limitation of the pinned parser, verified in its local source during T02fix1: pdf-0.10.0/src/object/types/pagesnode.rs:55–60 starts searching with page_limited(..., 16) and rejects when that budget is exhausted; file.rs:825–827 uses that search. An exceptionally deep valid page hierarchy may therefore fail the probe. Retain the safe “This PDF cannot be validated” diagnostic without asserting corruption. Do not replace the dependency in this slice. Custom MediaBox resolution must support inheritance and detect cycles without a different arbitrary threshold or claims of unlimited support the parser does not offer.

Mmap was rejected because of its unsafe contract under external modifications. Windows.Data.Pdf was also rejected: [Microsoft requires package identity for PdfDocument/PdfPage](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/winrt-api-desktop-app-support), which the defined NSIS packaging does not provide. Do not change packaging to incorporate that API. The complete research is retained in `work/reviews/task02-pdf-validation-preflight.md`.
