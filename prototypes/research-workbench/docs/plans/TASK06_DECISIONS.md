# T06 — decisiones semánticas de P2 y candidatos

Estado: Accepted por Sol tras revisión independiente PASS, ADR-023, antes de T05/T06. Normativa semántica complementaria de CONTRACTS/WORKFLOW_GATES/TASK05_PORTS. Sin implementación nueva, wire/DTO/JSON v1/ontología/dependencias adicionales. La ABI interna concreta del preflight sigue como propuesta y debe contrastarse con T05 integrada antes del despacho. T04c no cambia por este documento.

1. setP3Candidate nuevo exige P2 iniciada, aunque no activa; no touch/inicio/aceptación implícitos. Replay previo; lifecycle Workflow preservado. Summary lectura incluso NOT_STARTED/ARCHIVED, sin crear fila. Coste: no precandidatos persistentes antes de P2; captura T05 sigue permitida sin iniciar fase.
2. set expresa decisión completa: estado final cero requiere justificación canónica no vacía (1..5000 recibidos antes normalizar); estado final con candidatos exige null. Escribe resolución ANSWERED, explanation=null; conserva answerText preexistente. Última deselección sin motivo rechaza atomicamente. Save candidato permite PENDING/null como borrador, summary deriva candidatos de asociaciones y justificación null sin inventar selección; gate pendiente. Si structuredValue está presente, sólo objeto completo cerrado con candidates/count iguales a DB. Coste: permitir borrador null exige rama explícita, no aceptar objetos parciales o reparar discrepancias.
3. selected=false exige priority/rationale=null; no ignorarlos. selected=true exige claim/question ACTIVE con asociación paper_items directa, prioridad null o entero1..5, rationale1..5000 canónico. Deseleccionar claim/question archivado está permitido si Paper/fase admiten mutación. CAS antes no-op; no-op sólo tras validar petición/resultado; no revision item por cambiar selección. Coste: cliente debe limpiar campos irrelevantes antes de enviar, error explícito para payload ambiguo.
4. Archivar/restaurar candidato conserva selección/count en paper_items; summary incluye seleccionados archivados. Gate P2 considera inválido candidato archivado; UI lo etiqueta y permite deseleccionar. Archive no reescribe respuesta candidata si proyección no cambia. No selección implícita durante restore; sólo persiste elección anterior. Coste: count de cola incluye entradas inválidas señaladas, evita ocultación o cambio silencioso de selección.
5. Save de candidata no cambia asociaciones. ANSWERED requiere proyección completa/justificación coherente con DB, explanation=null; no interpretar answerText. Set actualiza fila de respuesta sólo si los cuatro valores canónicos cambian; primera revision1, incrementos atómicos con clock e historial. Los eventos efectivos registran antes/después y requestId, no payloads en logs. Colisión de requestId/replay mantienen prioridad vigente.
6. Preguntas PRE se muestran como contexto; usuario captura Question enlazada al Paper y la vincula explícitamente a main_questions_processed. Sin NLP/LLM ni FK nueva para fragmentos de prosa PRE. Coste: asociación contextual manual, no identidad por pregunta PRE que el wire no soporta.
7. Habilitación simple: T06a habilita únicamente candidatos reales y policy P2 probada con fixtures explícitas. **Todos** los saves/evaluate/advance P2 de producción permanecen UnsupportedCapability hasta T07, sin habilitación parcial por key. T06b entrega captura Knowledge/Concept y cola P3 operativas; muestra formularios P2 completos sólo cuando las capacidades existentes knowledge+concepts+relations+provenance están disponibles. Sin flag público nuevo. T07 conecta resolutores completos y habilita guardado/evaluación/aceptación como conjunto. Tests internos pueden proporcionar P2Context completo con fixture, jamás simularlo como capacidad de producto. Coste: procesamiento formal P2 se habilita un hito después; se evita disponibilidad parcial complicada e inferir ausencia de tablas vacías.

Organización aceptada: T06a backend/candidatos/policy, T06b UI captura/P2, cada uno autor nuevo después T05a/b y revisión. Shared files transferidos explícitamente, sólo un implementador producto. Firmas propuestas preflight siguen pendientes de verificar contra T05; no publicarlas aún como implementadas. Ninguna migración0003/checksum se reescribe para facilitar T06.

Revisión documental independiente PASS: docs/reviews/task-06/rulings-review.md. Las decisiones preservan cierre/inversa, CAS/replay y fuentes únicas; no acreditan implementación. La excepción de save PENDING/null y justificación cero sólo estará disponible cuando se habilite save P2 en T07. En T06, cero items no permite guardar esa justificación ni fabricar itemId para set.
